**Question:** how should a guest verify a phone number when the request did not include the SMS opt-in, and how should a corrected phone number get its own opt-in before a code can be texted to it?

- **Who answers:** the owner, with the attorney review of the SMS wording ([[OQ-ATTORNEY-PRIVACY]]); the 10DLC campaign's opt-in description ([[OQ-BIRD-10DLC]]) names where opt-in happens.
- **Known:** [[OWN-DEC-96]] verifies email and phone separately by a one-time code from the receipt; [[HH-INT-22]] sends no text, codes included, to a number without a current SMS opt-in, and the opt-in is the request form's checkbox with its disclosure ([[OWN-DEC-147]]). A code by voice call is not decided.
- **Options (not decided):** (a) keep phone verification by text only, for numbers with the opt-in; (b) offer the request form's SMS checkbox and disclosure again on the receipt for the number being verified or corrected (a second opt-in point the 10DLC registration would have to describe); (c) verify by a voice call (needs Bird voice and wording).
- **Until answered (TSK-0033):** the phone is verified by text only when this request gave the SMS opt-in and it is still current; otherwise the receipt says the phone stays unverified and offers email verification. Change Contact changes the email only; a phone number is not changed on the receipt (staff correct it with a reason, ROLE-MATRIX). Whether a number has an opt-in from another request is never used or shown (HH-ID-03).
