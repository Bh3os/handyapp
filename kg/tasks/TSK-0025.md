Goal: An idempotent submission endpoint that creates exactly one request and its customer, contact, property and project records.

Scope:
- Migrations: `customers`, `contacts`, `properties`, `projects`, `requests`, `request_services`, `request_answers`.
- `POST /api/public/requests` with Idempotency-Key; one transaction creating the records plus outbox events (staff intake item, receipt).
- Rate limits and quiet spam controls (honeypot, timing, per-IP) without forcing accounts; no automatic matching to existing customers.

Done when:
- Integration tests: double submit and retry give one request; changed body with the same key is a 409; rate-limited requests get a neutral error.
- The `tested_by` scenarios pass for this slice; tests are tagged with the `implements` IDs.
- CI green: `secrets`, `test` (lint, typecheck, unit, integration) and `e2e`.
