Goal: Server-side state machines with named events and useful denial reasons, and separate state dimensions per job.

Scope:
- `packages/domain`: transition tables for Request, Project, Estimate version, Job, Visit, Hold, Invoice, Payment and Case; `apply(entity, event, context)` returns the next state or a reason.
- Separate dimensions for operational, visit, hold, quality and financial state; no generic set-status function.
- Feature tasks add their entity rules here; this task ships the engine and the Request and Project tables.

Done when:
- Unit tests: every invalid transition is rejected with a reason; closeout and cancellation cannot skip required states.
- CI green: `secrets`, `test` (lint, typecheck, unit, integration) and `e2e`.
- Graph: this task set to `status: done`; `node tools/kg.mjs index && node tools/kg.mjs lint` reports 0 problems.
