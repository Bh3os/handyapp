Goal: Guardrails for any future AI assistance: untrusted input handling, authorization outside the model, bounded steps and a manual path.

Scope:
- Built only after the owner approves the AI plan; the AI module stays disabled and its disabled state stays tested.

Done when:
- Tests: model output can never authorize an action; disabled state unchanged.
- CI green: `secrets`, `test` (lint, typecheck, unit, integration) and `e2e`.
- Graph: this task set to `status: done`; `node tools/kg.mjs index && node tools/kg.mjs lint` reports 0 problems.

Done (2026-10-26, no migration): the guardrail framework, with AI disabled in every environment and no provider, model, SDK or key anywhere (`apps/server/src/platform/ai/`). An allowed-use registry declares each use [[HH-AUTO-03]] names (plus the Spanish-note drafts of [[OWN-DEC-211]]) with the policy action the requester must hold, its named inputs and their provenance, the actions a suggestion may propose, the person's review action and the manual path; bounds, privacy destination and instructions are NOT CONFIGURED, and a use with any of them unset is refused. Inputs are minimised to the declared fields, never include credentials, access codes, card details, photos, documents or contact details ([[OWN-DEC-15]]), are redacted of card numbers, phone numbers, emails and written codes, and stay labelled data, never instructions. A model answer becomes a suggestion only under the [[OWN-DEC-14]] contract (no extra fields, no self-verification, no invented record IDs or actions) and is never applied; reviewing it is the policy's decision on the person and the server's record only. The gateway refuses every request with AI_DISABLED first (kill switch: `ai.module`, which can only be off), returns the manual path, and audits each refusal (`ai.assist`, denied) without input contents. Tests prove model output never authorizes, nothing is sent, no AI SDK, key or provider host exists, and the disabled state is unchanged. PROPOSED details: [[OQ-AI-GUARDRAILS-DETAILS]].
