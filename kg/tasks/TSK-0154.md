Goal: MFA is required for every active staff account (Owner, Office/Dispatcher, Estimator, Worker), as decided in [[OWN-DEC-202]]; it can no longer be optional.

Scope:
- First inspect the TOTP enrollment, recovery codes and challenge built by [[TSK-0015]] (`apps/server/src/modules/identity/mfa.ts`) and keep them; no second MFA system.
- Enforced enrollment: an active account without a factor is sent to TOTP enrollment (with recovery codes shown once) right after password sign-in, before any staff screen. A session that has not passed the second factor is a restricted pre-MFA session that only reaches the enrollment and challenge routes.
- No access to staff routes or staff API operations without completed MFA, enforced on the server for every role; no role, flag or configuration value turns it off. Remove the "MFA optional" recommendation banner and the optional wording in the staff catalogs (English and Spanish).
- Recovery and reset through the Owner: the Owner resets a staff member's factor (audited, with a reason; all their sessions revoked; enrollment required at the next sign-in). The Owner's own lost factor: recovery codes or the safe bootstrap path (PROPOSED in [[OWN-DEC-202]]); never a bypass.
- Offboarding and reactivation per [[OWN-DEC-202]] and [[OWN-DEC-200]]: disabling clears the password and removes the factor and recovery codes; reactivation goes through a secure single-use link, the Owner's permission review and a new enrollment.
- Existing-accounts migration: accounts active today without a factor are flagged and enrol at their next sign-in; nothing is lost from their IDs, roles, assignments or audit records; the bootstrap Owner enrols on first sign-in.
- E2E helpers: the staff sign-in helpers enrol TOTP for synthetic test accounts and compute codes from the test secret (never a real secret, never logged), so every staff e2e journey runs with MFA on; staging Reset Test Data ([[TSK-0141]]) seeds test accounts in a state the helpers can enrol.
- Audit entries for enrollment, challenge failure, factor reset and recovery-code use ([[HH-SEC-06]]).

Done when:
- Tests: each of the four roles is refused every staff route and API operation until enrollment and the challenge are complete; a pre-MFA session cannot read or write anything else; an Owner factor reset revokes sessions and forces re-enrollment; a recovery code works once; offboarding removes the factor and a reactivated account must enrol again; a migrated account without a factor is forced to enrol; no configuration makes MFA optional; fresh authentication still works with TOTP.
- The `tested_by` scenarios pass for this slice; tests are tagged with the `implements` IDs.
- CI green: `secrets`, `test` (lint, typecheck, unit, integration) and `e2e`.
- Graph: this task set to `status: done`; `node tools/kg.mjs index && node tools/kg.mjs lint` reports 0 problems.

Built (2026-10-22, migration 0071): the TOTP authenticator, challenge and recovery codes of [[TSK-0015]] are reused and made mandatory for every staff role. Sign-in answers 202 with `step: enroll` (no authenticator) or `step: verify`; the enrolment and pending sessions reach only the routes the route contract marks `beforeSecondFactor` (sign-in, sign-out, password links, enrol, confirm, verify) and every other staff route answers UNAUTHENTICATED / MFA_REQUIRED before validation; the database refuses a complete session without a confirmed authenticator and the session resolver revokes one as `mfa_required`. Migration 0071 ended the live sessions of accounts without an authenticator (they enrol at their next sign-in, nothing else changes) and removed the authenticators of accounts already disabled. Offboarding removes the authenticator and recovery codes; the Owner resets a lost one (`staff.reset_mfa`, PROPOSED in the grant row: fresh sign-in, a reason, never oneself); the self-service removal and the recommendation banner are gone (staff catalogs EN and ES). Without MFA_ENCRYPTION_KEY staff sign-in is refused everywhere (fail closed, operator log MFA_NOT_CONFIGURED); local and ci tests configure a synthetic key. The approval check of [[TSK-0130]] (OWNER_MFA_REQUIRED) stays behind the new gate: a password-only Owner session never reaches publishing. E2E: every staff journey enrols TOTP on an account's first sign-in and gives codes computed with otpauth from the sealed test secret (apps/e2e/mfa.ts); the bootstrap Owner enrols in the first spec. PROPOSED: the Owner's own lost authenticator is recovered with a recovery code or the host-shell command `staff-access reset-mfa <email> <reason>`; a password-only session must complete the second factor within 10 minutes; fresh authentication keeps password or authenticator code. Not built here: the Owner's permission review on reactivation ([[TSK-0151]]); Reset Test Data ([[TSK-0141]]) needs no special seeding, as accounts without an authenticator enrol at sign-in.
